# Requisitos UX

- Selección buscable integrada dentro del selector, no dos campos de búsqueda y selección separados. Mostrar nombres amigables, filtrar compatibles, permitir retirar hasta el último destino; vacío es inválido, nunca equivale a todas las luces. Usar selectores oficiales HA cuando sean viables. IDs estables en backend, no nombres como claves.
- No exigir YAML, JSON, entity_id ni AND/OR/NOT para uso habitual. Opciones avanzadas plegadas inicialmente. Mantener capacidades avanzadas existentes, incluso al editar datos heredados no representables; impedir guardados destructivos y ofrecer editor compatible.
- Guardar mediante operación explícita, validación cliente y servidor, bloqueo de doble envío mientras espera, confirmación real antes de mostrar éxito. Resolver conflictos mediante revisión optimista y opciones claras de recargar/reconciliar; no sobrescribir silenciosamente. No perder foco o borrador por actualizaciones hass o recarga de entrada; conservar cambios ante error, desconexión o permisos insuficientes.
- Vista previa local no envía órdenes a luces. Una prueba física, si se aprueba, debe ser explícita, autorizada y temporal. No simular como si fuera estado real; distinguir modo solicitado, efectivo, enmascarado y no disponible.
- Luces: solo las autorizadas, validar dependencias al desautorizar; ningún comando a luces ajenas. Zonas: nombre amigable, área opcional, luces autorizadas. Modos: zona, nombre, color, brillo, efecto, switch opcional, vista previa, prioridad/transición avanzadas; exclusividad por zona, recuperar intención vigente.
- Numérico: sensor compatible, unidad real, destino, puntos únicos ordenados, cambio gradual o por rangos, simulación; conservar unidades de la regla, validar límites y estados inválidos. Si se cambia unidad/métrica pedir confirmación y recalibración; nunca reinterpretar valores en silencio.
- Estado: sensor, estado compatible, destinos, color, brillo, efecto, espera opcional; desconocido/no disponible no activa ni prolonga una alarma como estado válido. La espera es propuesta hasta verificar contrato y pruebas.
- Notificación: aviso por nombre, destinos, color/brillo, efecto, duración, periodo cuando aplica, prioridad; previsualización con temporizador local. Habilitar/deshabilitar, probar en simulación, editar, eliminar. No asumir recepción automática de Alexa/telefono.
- Horarios: días locales HA, inicio inclusivo/final exclusivo, día de inicio para intervalos nocturnos; validar día y horas. Regla avanzada: todas/cualquiera de las condiciones, comparadores amigables y horario opcional; no degradar arboles existentes.
- Configuración: general, ajustes reales del motor, diagnóstico real y acceso a Options Flow. Recuperación configurable pendiente D, no controles ficticios. Sin dependencia obligatoria de Alexa, Matter Hub ni nube. Seguridad luminosa complementaria, no sistema certificado.
